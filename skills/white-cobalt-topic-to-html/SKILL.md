# 주제 → 조사·원고 → White Cobalt HTML

**주제와 요구사항만으로 시작하며 Markdown 파일은 필수가 아니다.**
조사한 내용을 내부 원고 `topic.md`로 먼저 작성하고 최종 읽는 HTML `topic.html` 하나로 만든다.
기존 원고를 변환하는 MD→HTML과 구분하며 이 스킬이 조사부터 제작까지 담당한다.

**최종 전달물은 자원을 내장한 HTML 파일 하나다.**
[단일 HTML 마감 절차](references/single-file-html.md)를 반드시 수행한다.
조사 원고·장 조각·자산 폴더는 내부 작업용이며 사용자가 별도로 요청할 때만 제공한다.

이 폴더 하나만 복사한다. 원래 레포·형제 스킬·특정 검색 MCP는 필요하지 않다.
[주제 조사와 원고 작성](references/topic-authoring.md),
[독립 사용·디자인 규칙](references/guide.md), [deck.html](deck.html)을 읽는다.
`SKILL_DIR`은 이 `SKILL.md`가 있는 폴더의 절대 경로다.

## 수행 순서

1. 주제·대상·목적·분량·출력 위치를 정한다. 주제가 없거나 식별이 모호하면 확인한다.
   나머지 기본값은 조사 지침에 따라 명시한다. 자료 제작을 실제 배포 요청으로 해석하지 않는다.
2. 공식 문서로 기능·출시 상태·지원 범위·제약을 조사하고 URL·확인일·근거를 기록한다.
   소스 종류·API·포털의 지원 차이를 제품 이름 하나로 묶지 않는다.
3. 배경·핵심 개념·아키텍처·흐름·예시·주의점·도입 판단을 Markdown 원고로 먼저 작성한다.
   장별 핵심 메시지·시각 구조·상세 설명·발표 스크립트·출처를 남긴다.
4. 원고에 맞춰 White Cobalt 20종을 선택한다. **맞는 템플릿이 없으면 같은 스킨의
   새 레이아웃을 만들어 사용한다.** 내용은 기존 칸에 억지로 맞추지 않는다.
5. 원고와 시트의 의미·숫자·표·출처·노트를 대조하고 넘침·겹침·모바일·인쇄를 확인한다.
   조사나 렌더가 막히면 확인하지 못한 항목을 분명히 밝힌다.

**스킨:** 순백 `#FFFFFF`, 니어블랙 `#0E0E0E`, 코발트 `#0F62FE`,
IBM Plex Sans KR/Archivo, 각진 블록·가는 선. 네이비 도형에 색만 바꾸지 않는다.
좌측 목차·세로 스크롤·장별 설명/스크립트·접기·키보드 조작은 공통 읽기 UI를 유지한다.
기술 구성도는 경계·방향·범례를 그리고 논리 예시와 실제 배포를 구분한다.
특정 회사·제품·산업에 종속되지 않는다.

## 독립 실행과 전달

주제 조사와 Markdown 원고 작성은 에이전트가 수행한다. 아래 도구는 작성된 HTML 조각의
조립·검사만 담당하며 웹 검색이나 임의 주제의 자동 원고 생성기는 아니다.

```sh
python3 "$SKILL_DIR/scripts/build_html.py" chapters.html \
  --title "주제 제목" -o output/topic.html
node "$SKILL_DIR/scripts/verify.cjs" output/topic.html
```

동봉 `package.json`과 독립 사용 규칙으로 실행 환경을 준비한다.
최종 HTML 하나에 필요한 자원을 내장하고 출처 확인일·가정·미확인 사항·검증 한계를 전달한다.
외부 웹 접근이 없으면 최신 사실을 확인한 것처럼 쓰지 않으며, 제공된 원본 자산과 내용은 보존한다.
