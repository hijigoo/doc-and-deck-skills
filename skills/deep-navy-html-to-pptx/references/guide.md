# 독립 스킬 사용 규칙

이 안내는 해당 스킬 폴더에 포함된다. **이 폴더 하나만 복사하면 되며 원래 Git 저장소,
형제 스킬, 다른 `pptx` 스킬을 설치할 필요가 없다.** 이 스킬은 에이전트가 원고와 레이아웃을
작성하는 워크플로이지, 모든 Markdown/HTML을 무조건 자동 변환하는 프로그램은 아니다.

**HTML → PPTX에서는 [원본 보존 포팅 절차](pptx.md)가 우선이다.**
아래 신규 원고용 레이아웃 선택·재구성 규칙을 기존 HTML의 재조판 허용으로 해석하지 않는다.

## 경로와 실행 환경

`SKILL_DIR`은 지금 읽는 `SKILL.md`가 있는 폴더의 절대 경로다. 예를 들어 다음처럼 설정한다.
경로에 공백이 있어도 동작하도록 명령에서 항상 따옴표를 쓴다. PowerShell에서는 환경 변수
문법을 맞추거나 같은 절대 경로를 명령 인수로 직접 사용한다.

```sh
SKILL_DIR="/absolute/path/to/the-skill"
```

결과물과 생성 코드는 사용자의 작업 폴더에 저장한다. 설치된 스킬 자체는 결과물 폴더로
사용하지 않는다. 동봉된 파일을 찾을 수 없으면 복사 누락을 명확히 보고한다.
없는 파일을 원래 레포에서 몰래 내려받거나 다른 스킬에서 찾지 않는다.

| 작업 | 별도로 준비할 표준 실행 환경 |
|---|---|
| 완성 HTML 열기/직접 편집 | 브라우저와 파일 편집 도구 |
| HTML 조각 조립 | Python 3.9 이상, 표준 라이브러리만 |
| 브라우저 자동 검사 | Node.js 22 이상, 동봉 `package.json`의 Playwright, Chromium |
| PPTX 읽기·자산 추출 | Python과 해당 스킬의 `requirements.txt` |
| PPTX 쓰기 | Node.js와 해당 스킬의 `package.json` |
| PPTX 원본 렌더·실제 시각 확인 | PowerPoint 또는 LibreOffice, PDF/이미지 변환 시 Poppler |

표준 패키지·앱은 스킬에 내장하지 않는다. 필요할 때 **스킬 폴더의 명세**로 설치한다.
스킬 경로가 읽기 전용이면 폴더 전체를 쓰기 가능한 작업 위치로 복사한 뒤 설치한다.

```sh
npm install --prefix "$SKILL_DIR" --no-audit --no-fund
cd "$SKILL_DIR"
npx --no-install playwright install chromium
```

Python 변환 도구가 있는 스킬은 작업 폴더의 가상 환경에서 실행한다.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r "$SKILL_DIR/requirements.txt"
```

일반 HTML 작성에는 위 패키지 설치가 필요하지 않다. 웹폰트는 네트워크가 필요하며,
오프라인 배포 시 이용 조건을 확인한 폰트를 포함하고 대상 환경에서 다시 확인한다.
실행 환경이나 폰트가 없으면 무엇이 필요한지 알리고, 누락된 검사를 통과했다고 하지 않는다.

## 신규 원고: 내용과 스킨

동봉 `deck.html`이 이 스킬의 디자인 기준이다. 읽기 UI는 좌측 목차, 세로 스크롤,
장 제목, 장별 설명/스크립트, 접기, J/K·N·M, 모바일 서랍, 인쇄를 제공한다.
Deep Navy와 White Cobalt의 내부 배치는 다르며 같은 도형에 색만 바꾸지 않는다.

1. 원고의 주제·순서·전체 표·항목·상세·출처를 읽고 장을 나눈다.
2. 제목·핵심 메시지·정보 관계에 맞는 템플릿을 고른다.
3. **적합한 템플릿이 없으면 같은 스킨의 새 레이아웃을 만들어 사용한다.**
   별도 승인 없이 설계·검증할 수 있으며 내용을 기존 칸에 억지로 맞추지 않는다.
4. 본문에는 핵심 도식·비교·맥락을 배치하고 긴 설명과 제공된 스크립트는 설명란에 보존한다.
   글씨를 줄이거나 근거 없는 수치·장식으로 여백을 채우지 않는다.
5. 본문·노트·이미지·출처를 원고와 대조하고 실제 크기와 모바일·인쇄를 확인한다.

템플릿 선택은 개수보다 정보 관계가 우선이다.

| `data-layout` | 적절한 정보 구조 |
|---|---|
| `cover` | 주제와 읽는 관점 |
| `contrast` | 두 상태·관점의 대조와 전환 |
| `architecture` | 구성 요소·역할·포함 관계 |
| `process` | 단계별 작업과 인계 |
| `matrix` | 같은 기준에 따른 비교 |
| `scenario` | 역할·상황·행동 |
| `checklist` | 검토 기준과 진행·보류 판단 |
| `evidence` | 근거·해석·한계 |
| `roadmap` | 단계·산출물·전환 조건 |
| `dataflow` | 데이터 수집·변환·저장·소비 |
| `sequence` | 참여자별 요청·응답 순서 |
| `network` | 접근 구역과 허용·차단 경로 |
| `metrics` | 값·단위·비례 차트·해석 |
| `walkthrough` | 원본 코드/화면과 번호 주석 |
| `decision` | 두 조건과 세 결과를 연결하는 의사결정 트리 |
| `pyramid` | 기반에서 확장으로 읽는 단계별 우선순위 |
| `funnel` | 기준에 따라 후보를 좁히는 정성적 선정 흐름 |
| `riskmap` | 영향과 가능성을 구분하는 위험도 맵 |
| `swimlane` | 역할 × 단계별 행동과 인계 책임 |
| `closing` | 결론과 다음 행동 |

추가 판단·협업 배치를 편집할 때도 정보 관계를 보존한다.
`decision`의 조건·예/아니오 라벨·결과를 함께 바꾸며, 실패 경로를 생략하지 않는다.
`pyramid`와 `funnel`의 기본 면적·폭은 정성적 구조다. 수치를 표현한다면 도형 비례와
라벨·단위·근거를 함께 맞춘다. `riskmap`은 영향이 위로, 가능성이 오른쪽으로 커진다.
구역 위치를 검증한 사실과 가정으로 구분한다. `swimlane`은 역할별 행과 단계별 열,
전체 셀 내용을 보존하며 색상만으로 승인·책임 상태를 전달하지 않는다.

## HTML 작성과 조립

`deck.html`을 결과물로 복사해 직접 편집하면 별도 빌더 없이 열린다.
예제 장은 `article.chapter`, 시트는 `.sheet > .slide`, 상세는 `.note-body`다.
기본 시트의 1920×1080을 유지한다. 원본 PPTX 입력은 원래 종횡비가 우선이다.
`.ch-t`·`.ch-part`·`data-part`를 갱신하고 장 안에 `article`을 중첩하지 않는다.
번호·목차·장 링크는 내장 런타임이 만든다.

기존 조각을 조립할 때만 동봉 도구를 선택적으로 사용한다.

```sh
python3 "$SKILL_DIR/scripts/build_html.py" chapters.html \
  --title "문서 제목" --subtitle "한 줄 부제" -o output/document.html
```

`chapters.html`에는 `.sheet` 하나와 `.note-body`를 갖는 `article.chapter`들이 있어야 한다.
이 명령은 Markdown을 파싱하지 않는다. 에이전트가 원고를 읽고 시트 HTML을 작성한 다음
조립한다. 템플릿은 이 스킬 안의 `deck.html`만 사용한다.
원본 SVG 심볼이 별도로 있으면 `--icons original-symbols.svg`로 그대로 넣을 수 있다.

`slot:*` 주석은 텍스트 교체 위치다. 직접 HTML을 편집해도 된다.
공통 키는 `title`, `lead`, `context`, `insight`, `caution`이다.
제목은 완전한 문장으로 넣고 각 키는 한 번만 쓴다. 항목은 `item1-title`/`item1-body`,
매트릭스는 `head1`–`head3`과 `cell1-1`–`cell3-3`을 사용한다.
기술 도해의 값·관계·코드 행은 문자열만 바꿔 끝내지 않고 기하와 연결도 함께 갱신한다.

## 기술 다이어그램과 자산

논리·개념·실제 배포 구성을 먼저 구분해 표시한다. 기본 예제는 제품·산업에 무관한
가상 도식이며 서비스의 실제 지원 기능·접속 경로·보안 보장을 뜻하지 않는다.

- 노드·외부 사용자·포함 경계·요청/데이터 방향·인증·관측을 구분한다.
  실선/점선의 뜻을 범례로 보이며 화살표가 글자나 박스를 관통하지 않게 한다.
- 실제 클라우드·리전·가상 네트워크·Private 연결·권한 전달은 공급자 문서로 확인한다.
  확인하지 않은 연결은 제안으로 구분하고 근거를 설명란에 둔다.
- HTML/인라인 SVG 또는 사용 가능한 편집 도구로 새 구조를 그릴 수 있다.
  외부 다이어그램 렌더러가 없으면 내장 SVG/HTML을 사용한다. 그림에는 제목/설명을 붙인다.
- 원본 이미지·로고·아이콘은 그대로 복사하고 해시·크롭·비율·레이어를 유지한다.
  유사 자산·이모지로 대체하거나 스킨에 맞춰 로고를 재색상하지 않는다.
  새 아이콘은 필요한 경우에만 공식 자산과 이용 조건을 확인한다.
- 차트는 0 기준 막대 축·단위·최대값·숫자 표·실제 길이를 일치시킨다.
  템플릿의 가상 값을 고객 성과로 인용하지 않는다.
- 시퀀스는 참여자·요청/반환 방향·순서를 함께 고친다. 코드/화면 주석은 실제 행·위치와
  연결한다. 의사 코드를 실행 가능한 SDK 예제라고 설명하지 않는다.

## 기존 PPTX 우선 규칙

기존 PPTX가 주어지면 기본은 **원본 보존**이다. 위의 새 레이아웃 자유를 이유로
내용·순서·배치·표·그림을 다시 구성하지 않는다.

- 제목·문구·수치·표의 모든 행/열·주석·출처·노트·숨김 상태를 유지한다.
  본문을 줄이고 접힌 상세에만 원문을 보관하는 것도 누락이다.
- 미디어뿐 아니라 마스터·레이아웃·그룹·SVG 대체 표현을 확인한다.
  원본은 수정하지 말고 작업용 복사본을 쓴다.
- 시트 디자인이 스킨과 충돌하면 원본 시트가 우선이다. 스킨은 바깥 읽기 UI에 적용한다.
- 복합 도형을 직접 옮기기 어렵다면 원본 프로그램의 PDF/SVG/이미지 렌더로 보존한다.
  편집 가능한 HTML이나 애니메이션·영상까지 복제했다고 주장하지 않는다.
- 오타나 오래된 정보도 몰래 고치지 않는다. 추가 설명은 원본 밖에 구분한다.
  요약·재구성은 사용자가 명시적으로 요청한 경우에만 수행한다.

## 확인과 전달

```sh
node "$SKILL_DIR/scripts/verify.cjs" output/document.html
```

이 도구는 1600/768/390px에서 장 수·목차·노트·종횡비·넘침·이미지·실행 오류를 검사한다.
추가로 직접 열어 한글·시트 밀도·텍스트 겹침·다이어그램 방향·표 값을 확인한다.
기존 PPTX는 전 장 원본 렌더와 시각 비교하고 자산 해시·노트·순서를 대조한다.
PowerPoint 출력은 파일 구조 검사에 더해 실제 앱에서 열고 렌더를 확인한다.

결과 파일과 필요한 자산 폴더를 함께 전달한다. 사용한 폰트, 렌더 앱, 이미지로 보존한
영역, 생략할 수밖에 없었던 기능과 실행하지 못한 검사를 명확히 보고한다.
