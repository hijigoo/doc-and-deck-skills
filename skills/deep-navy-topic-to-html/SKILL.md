# 주제 → 조사·원고 → Deep Navy HTML

**입력은 주제와 요구사항이며 Markdown 파일은 필수가 아니다.**
주제를 조사해 내부 원고 `topic.md`를 먼저 만들고 최종 `topic.html` 하나를 전달한다. 기존 원고를 디자인하는
MD→HTML 작업과 구분하며, 이 스킬 안에서 조사·작성·HTML 제작까지 수행한다.

**최종 전달물은 자원을 내장한 HTML 파일 하나다.**
[단일 HTML 마감 절차](references/single-file-html.md)를 반드시 수행한다.
조사 원고·장 조각·자산 폴더는 내부 작업용이며 사용자가 별도로 요청할 때만 제공한다.

이 폴더 하나만 복사한다. 원래 레포·형제 스킬·특정 검색 MCP는 필요하지 않다.
[주제 조사와 원고 작성](references/topic-authoring.md),
[독립 사용·디자인 규칙](references/guide.md), [deck.html](deck.html)을 읽는다.
`SKILL_DIR`은 이 `SKILL.md`가 있는 폴더의 절대 경로다.

## 수행 순서

1. 주제·청중·목적·분량·출력 위치를 정한다. 주제가 없거나 대상을 식별할 수 없으면 확인한다.
   나머지 기본값은 조사 지침대로 명시한다. 이 작업은 설명 자료 제작이며 실제 배포가 아니다.
2. 공식 문서 중심으로 조사한다. 기능·GA/Preview·지원 조건·제약·출처 URL·확인일을 기록한다.
   검색 결과나 제품 소개를 검증된 운영 사실로 간주하지 않는다.
3. 배경 → 핵심 개념 → 구조/흐름 → 적용 예시 → 제약/판단 순서로 Markdown을 먼저 작성한다.
   각 장에 제목·메시지·시각 구조·상세 설명·발표 스크립트·출처를 넣는다.
4. 동봉 20종을 골라 Deep Navy HTML을 만든다. **내용에 맞는 템플릿이 없으면 같은 스킨의
   새 레이아웃을 만들어 사용한다.** 기존 칸에 억지로 맞추지 않는다.
5. 원고와 HTML의 주장·표·수치·노트·출처를 대조하고 화면·모바일·인쇄를 확인한다.
   실행하지 못한 조사나 검사는 완료로 표시하지 않는다.

**스킨:** 웜 페이퍼 `#F4F2ED`, 네이비 `#0E2340`, 코발트 `#2C6BED`,
Manrope/Pretendard. 목차·세로 스크롤·장별 설명/스크립트·접기·키보드 조작을 유지한다.
기술 관계에는 아키텍처·데이터 흐름·시퀀스를 쓰고 개념도/실제 배포를 구분한다.
특정 제품·산업을 필수 전제로 삼지 않는다.

## 독립 실행과 전달

에이전트가 작성한 HTML 조각을 조립할 때만 다음 명령을 쓴다. 주제 조사와 Markdown 작성은
이 스크립트가 자동 수행하는 기능이 아니다. 외부 웹 접근이 없으면 최신 사실을 확인했다고 하지 않는다.

```sh
python3 "$SKILL_DIR/scripts/build_html.py" chapters.html \
  --title "주제 제목" -o output/topic.html
node "$SKILL_DIR/scripts/verify.cjs" output/topic.html
```

실행 환경은 동봉 `package.json`과 독립 사용 규칙을 따른다.
최종 HTML 하나에 필요한 자원을 내장하고 출처 확인일과 가정·미확인 사항·검증 한계를 전달한다.
원본 파일이 제공되면 그 자산과 보존 조건을 우선하며 몰래 요약·교정하지 않는다.
