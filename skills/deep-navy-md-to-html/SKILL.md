# Markdown → Deep Navy 읽는 문서

**최종 전달물은 자원을 내장한 HTML 파일 하나다.**
[단일 HTML 마감 절차](references/single-file-html.md)를 반드시 수행한다.
원고·장 조각·폰트·이미지 폴더는 내부 작업용이며 별도 결과물로 요구하지 않는다.

**이 스킬 폴더 하나만 복사해 사용한다.** 원래 레포나 형제 스킬은 필요하지 않다.
[독립 사용 규칙](references/guide.md)과 동봉 [deck.html](deck.html)을 읽는다.
`SKILL_DIR`은 이 `SKILL.md`가 있는 폴더의 절대 경로다.

1. 원고의 순서·핵심·상세·표·출처를 읽고 메시지에 맞는 장을 구성한다.
2. 동봉 20종에서 정보 관계에 맞는 템플릿을 고른다. **내용에 맞는 템플릿이 없으면
   같은 스킨의 새 레이아웃을 만들어 사용한다.** 별도 승인 없이 설계·검증하며 기존 칸에 억지로 맞추지 않는다.
3. 시트는 `.chapter > .sheet > .slide`, 설명·제공된 스크립트는 `.note-body`에 넣는다.
   `.ch-t`·`.ch-part`·`data-part`를 갱신하고 원본 이미지·아이콘은 그대로 복사한다.
4. 좌측 목차·세로 스크롤·장별 접기·J/K·N·M·모바일·인쇄 기능을 유지한다.
5. 원문과 결과를 대조하고 전체 시트의 한글·밀도·겹침·이미지·출처와 조작을 확인한다.

**디자인:** 웜 페이퍼 `#F4F2ED`, 네이비 `#0E2340`, 코발트 `#2C6BED`,
Manrope/Pretendard. 같은 스킨의 색·글꼴·선·여백 원칙을 유지한다.
표지·비교·구성도·근거·로드맵·데이터 흐름·시퀀스·네트워크·지표·코드 설명 등 20종은
출발점이지 제한이 아니다. 짧은 카드만 중앙에 띄우지 않고 정보 관계를 충분히 보여준다.
추가 CSS는 `.layout-*`로 한정한다. 긴 설명은 아래로 옮기며 글씨를 줄여 채우지 않는다.

직접 작성은 `deck.html` 복사·편집만으로 가능하다. HTML 조각을 조립할 때만 동봉 도구를 쓴다.
Markdown을 HTML로 구성하는 과정은 에이전트가 수행하며 조립기는 원고 자동 파서가 아니다.

```sh
python3 "$SKILL_DIR/scripts/build_html.py" chapters.html \
  --title "문서 제목" -o output/document.html
```

브라우저 자동 검사는 동봉 `package.json`으로 Playwright와 Chromium을 준비한 뒤 실행한다.
설치·경로·오프라인 폰트 조건은 독립 사용 규칙을 따른다.

```sh
node "$SKILL_DIR/scripts/verify.cjs" output/document.html
```

기존 PPTX가 함께 있으면 새 레이아웃 자유보다 원본 보존이 우선이다.
기술 도해는 개념/실제 배포를 구분하고 경계·방향·범례·값·출처를 확인한다.
모르는 기능을 보장하거나 원본을 요약한 카드로 바꾸지 않는다.
자원을 내장한 최종 HTML 하나와 확인하지 못한 한계를 전달한다.
